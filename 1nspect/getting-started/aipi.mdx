Some Standards of Practice allow (or require) inspectors to add their own information to the published report: installer qualifications, scope caveats, specific limitations, product-specific notes. 1nspecT stores this content as **Additional Information Provided by Inspector (AIPI)**. You can write it in two places:

- **Per inspection type**, in the **Limitations Text (AIPI)** tab. Use this when two kinds of inspection share a template and a narrative collection but need different limitations text, such as Residential Resale and Pre-Listing / Seller's.
- **Per narrative collection**, on the collection's card in the Narrative Library. This is the fallback, used when the inspection type has no text of its own.

Both places have a **Standard** text and a separate **Reinspection** text that prints on reinspection reports.

<Note>
AIPI is optional. Whether it is available (and how much it can say) depends on the SoP your template uses. Check your SoP's rules before adding one.
</Note>

## Per inspection type: Limitations Text (AIPI)

In the top bar, click **Narrative Management**, then open the **Limitations Text (AIPI)** tab. Only Owners and Admins can edit it.

There's one row per inspection type: Residential Resale, Pre-Listing / Seller's, New Construction (Final, Pre-Pour, Pre-Drywall), 11-Month Warranty, Historical Home, Limited Scope — Foundation/Structural, Commercial, Re-inspection and Custom. Each row has a **Standard** text and a **Reinspection** text.

- **Write** or **Edit** opens the AIPI editor (see [Editing an AIPI](#editing-an-aipi)).
- Before the text is saved, a dialog lists the inspections of that type that aren't published yet and will print it. It also says how many published reports keep their current text.
- **Use collection text** removes the type's text, so that type goes back to the narrative collection's AIPI.

An inspection's type is its **Inspection Type**. It's set from the primary service when the order is created, and you can change it in Inspection Details. See [Primary services](/1nspect/getting-started/primary-services).

## Per narrative collection (fallback)

In the top bar, click **Narrative Management**, then open the **Narrative Library** tab. Find the narrative collection's **card** and use its buttons: **Add/Edit Additional Information** and **Add/Edit Reinspection Additional Information**. A check mark shows once configured. The editor carries the note _"Used when the inspection type has no text of its own"_. These buttons are on the narrative-library cards, not on the Collection Detail page, and they are not available for caption libraries.

| Variant | Dialog title |
| --- | --- |
| **Standard AIPI** | _"Additional Information Provided by Inspector"_ |
| **Reinspection AIPI** | _"Reinspection — Additional Information Provided by Inspector"_ |

## Which text prints

The same text prints in the PDF, the client's online report and the Report Workspace preview. 1nspecT uses the first one that exists:

| Report | Order used |
| --- | --- |
| **Original inspection** | 1. The inspection type's Standard text. 2. The narrative collection's Standard AIPI. |
| **Reinspection** | 1. The inspection type's Reinspection text. 2. The collection's Reinspection AIPI. 3. The inspection type's Standard text. 4. The collection's Standard AIPI. |

If **Skip additional info** is set on an inspection, no AIPI prints.

Nothing changes until you write a type's text. Published reports never change: a new or edited text applies to reports published or republished from then on.

## Editing an AIPI

The AIPI editor is a rich-text dialog with the standard formatting tools:

- Bold, italic, underline
- Headings (H1, H2)
- Bulleted and numbered lists
- Font size
- Line spacing

Write the content you want to print on the report. Save when done. The editor validates that the content isn't empty before saving, and asks you to confirm you're responsible for the text.

### Reinspection framing

In the reinspection AIPI, write for a repair-verification context: scope limitations specific to the reinspection, caveats about what was and was not reinspected, how the report should be read in light of the original inspection.

## When to use AIPI

Typical uses:

- **Installer qualifications** that the SoP asks the inspector to disclose for specific equipment types
- **Scope caveats** when the inspection covered less than the standard (concealed areas, inaccessible systems, weather-constrained observations)
- **Limited-scope limitations**, such as a foundation/structural-only inspection (use the **Limited Scope — Foundation/Structural** row)
- **Reinspection limitations** that are different from an original inspection (one-visit scope, no new findings scope, follow-up fee structure)
- **Product-specific notes** that recur across many of your inspections (a known manufacturer defect, a disclosure your attorney has drafted)

## When not to use AIPI

AIPI is not the right place for:

- **Finding narratives.** Those live in the narrative library and are drafted per finding.
- **Standard disclaimers that print on every report.** Those are built into the report layout.
- **Legal agreements.** Those are your service agreement, built in **Business Ops › Contracts**.
