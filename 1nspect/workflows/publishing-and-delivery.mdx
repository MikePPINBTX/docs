Publishing locks the report and makes it available at a permanent URL. Delivery emails that URL to the client (and the agent) with a message you can personalize. Every report stays locked until the order is paid; the client and agent links return a Payment Required page until payment lands.

## Where to publish

Open the Report Workspace: **Inspections** top nav › the order › the inspection › Report Workspace. The **Publish Report** button is at the top of the page (**Republish vN** once a version exists).

## Prerequisites

Before Publish will accept the report:

- Every required SoP item is resolved (see [Pre-publish checks](/1nspect/workflows/pre-publish-checks))
- Every finding either has a narrative or has been signed off as Publish without narrative
- Required ratings and area comments are complete

If anything is missing, Publish shows a clear message naming the blockers. Resolve and retry.

## What Publish does

<Steps>
<Step title="Lock the inspection">
No more edits without a Republish. The inspection is immutable from this point.
</Step>
<Step title="Upload the final PDF">
1nspecT writes the final branded PDF to secure cloud storage.
</Step>
<Step title="Generate links">
The client's report link (permanent URL) and the agent's report link are generated. Each is served through short-lived signed URLs behind the permanent slug.
</Step>
<Step title="Record the publish">
The Order History gets a Publish event with the time, the version number, and the caller.
</Step>
<Step title="Fire the workflow trigger">
The matching workflow trigger fires:

- **Report Published — already paid** if the order is paid in full
- **Report Published — awaiting payment** if payment is still due
</Step>
</Steps>

## Deliver the report

When the order is already **paid**, Publish fires `report.published`, which sends the delivery emails you have configured in your workflow. When the order is unpaid, Publish fires `report.published.payment_pending` instead. The report **Delivered** trigger fires only on a Stripe payment after publish or when you use **Deliver** manually.

Use **Deliver** to send the report by hand.

The Deliver dialog captures:

- **Role**: Client or Agent (switches which subscriber-configured delivery template is used)
- **Email**: the recipient's address
- **Name**: who to greet
- **Custom message**: an optional personal note from you; it drops into the delivery email through the `$CustomMessage` tag if your template includes it
- **Preview**: 1nspecT renders a live preview of the subject and body of every delivery email that will send, with your custom message filled in

Send when the preview looks right.

## Payment-locked reports

Every published report is locked until the inspection is marked paid. Both the client's link and the agent's link return a Payment Required page until payment is recorded (via Stripe webhook or manual **Record Payment**). There is no setting to disable this.

See [Payment-locked reports](/1nspect/features/payment-locked-reports).

## Haven

If your account has Haven set up, a report that is **published and paid** is also sent to the client's Haven home binder as a link. Covered under integrations.

## Republishing

If you need to change the published report, Republish creates a new version. The permanent URL stays the same (so clients keep the link they already have), but a new version marker is attached. The Order History records both versions.

Use Republish sparingly: once a client has read a report and acted on it, changing the content can create confusion.

## Preview PDF without publishing

If you want the PDF but don't want to lock the inspection yet (for a walk-through with the client, for a draft review), use **Preview PDF**. It generates the PDF without locking, warns if there are publish blockers, and skips the slug generation.

## What the client sees

The client opens the report link in any browser. The report is a mobile-first web viewer with:

- Section-by-section navigation
- Summary filter
- Photo lightbox
- Equipment specs
- Reinspection results (if this is a reinspection report)
- A PDF download button for the official document

The PDF is the compliant deliverable; the web viewer is the easier-to-read version.
