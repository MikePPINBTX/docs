Two tools shape how a template prints on the final report. **Guided Layout** picks a Section Blueprint and a Summary Blueprint, then lets you tune style knobs. **Visual Page Designer** gives you zone-level control over the preamble page, section templates and summary page. Most residential subscribers never need the Visual Page Designer; Guided Layout is enough.

## Where to find each

Both tools are **Professional and Team only**. Open the template in **Templates** top-nav › the **Edit** icon on the card, then go to the **Visual Designer** tab. It offers **Guided Layout (pick + tune)** and **Open Visual Designer**. They do not open from the template card itself. The two routes are:

- Guided Layout Designer at `/templates/builder/[templateId]/guided-layout`
- Visual Page Designer at `/templates/builder/[templateId]/visual-designer` (also reachable at `/templates/designer`)

## Guided Layout

Click **Guided Layout (pick + tune)** on the Visual Designer tab. Pick:

- A **Section Layout Blueprint** — the printed structure for each inspection section (how findings are grouped on the page, where photos go, how multi-unit systems render)
- A **Summary** layout — what the report's summary contains and where it appears (see [Summary](#summary))
- **Style knobs** — fonts, colors and spacing within what the blueprint allows

### SoP-locked blueprints

The SoP your template is bound to can lock the blueprint choice. TREC and other official standards specify what section pages must look like, so for TREC templates the picker shows the single allowed blueprint with a lock icon. For a custom SoP or an InterNACHI template, you may see several blueprints to pick from.

The lock is enforced per blueprint ID: a template whose SoP's `allowedBlueprintIds` lists one ID shows that one as forced; a template whose SoP allows several lets you choose.

### Summary

The **Summary** step sets what the report's summary contains and where it goes.

**Layout.** Pick one:

- **Deficiency Summary**: the table of findings marked for the summary.
- **Findings at a Glance only**: count tiles for every reported deficiency (see [Findings at a Glance](#findings-at-a-glance)).
- **Findings at a Glance + Deficiency Summary**: both.

**Priority List** has been retired, because it printed the same table as Deficiency Summary.

**Findings at a Glance: count findings by.** **Kind** (Safety, Structural & Movement, Functional, Maintenance & Monitoring) or **Report section** (one tile per section). It only appears for layouts that include Findings at a Glance.

**Where should the summary appear?** **At the end of the report**, **Before the inspection sections** or **Right after the cover page**. Only the positions your standard allows are offered. TREC allows the summary only at the end of the report, and the step says so.

### Findings at a Glance

A block on the summary page that counts the report's deficiencies, headed **Findings at a Glance** (you can change the heading). It has these tiles:

- **Total Deficiencies Reported**
- **Safety**
- **Structural & Movement**
- **Functional**
- **Maintenance & Monitoring**

With **Report section** grouping, the tiles are your section names instead.

Under the tiles are **Inspection Limitations: N**, an optional **Informational Notes: N** line, and _"N of these M deficiencies are listed in the Deficiency Summary."_

It counts every reported deficiency, not only the ones marked for the summary. It never counts equipment spec captures, findings tagged Acceptable Performance, limitations or informational notes.

When the PDF includes the block, the client's online report shows the same tiles at the top. See [Publishing and delivery](/1nspect/workflows/publishing-and-delivery#findings-at-a-glance-in-the-online-report).

### Photo groups

When a finding has more than one photo, the report draws a thin border around all of that finding's photos so readers can see they belong together. That covers extra photos added with **＋ Photo** on the phone and photos of additional locations. A finding with a single photo isn't boxed. Captions are unchanged. This works with every photo position setting in the Guided Layout Designer.

- **Colour:** the box uses the template's accent colour, the same colour as the PDF's section headings. A new template takes this colour from **Settings › Branding** when it's created. Changing Branding later doesn't update existing templates, and there's no setting yet to change a template's colour after it's created.
- **Title (PDF):** the box is titled with the finding's headline, the bold first line of the narrative. When a finding has no separate headline, the photo caption is used instead. With the **Per finding** photo position (Guided Layout › Photos › Photo position), the box has no title, because the narrative sits directly above it.
- **Title (online report and Report Workspace):** there's no box title. The finding's own card, with its headline, is the first card inside the box.
- **Page layout:** each group starts on a new row, so a partly empty row before or after a group is normal. A large group can continue onto the next page, with the border shown on both pages.

## Visual Page Designer

Click **Open Visual Designer** on the Visual Designer tab (or go to `/templates/designer`). This is the advanced tool: direct zone-level control over every printed page.

### Three page types

A template has three types of printed pages, each with its own designer surface:

| Page type | What it is |
| --- | --- |
| **Preamble page** | The first page of the report after the cover: logo, title, custom zones |
| **Section templates** | The repeating layout for each inspection section |
| **Summary page** | Auto-populated summary with priority items and statistics |

For each type, add zones, position them, and define what content fills them at render time.

### Zones

A **zone** is a named region on a page. The zone-based report generator stamps inspection data into zones when the PDF is generated. Zones can carry:

- Dynamic text (property address, inspector name, inspection date)
- Dynamic photo grids (the inspection photos for this section)
- Dynamic finding cards (per subsection or per rating)
- Static text (your boilerplate)
- Static images (your brand elements)

### Findings at a Glance on the Summary page

On the Summary page, the zone palette has a **Findings at a Glance** zone. Its settings are:

- **Heading**.
- **Group findings by** (Kind or Report section).
- Switches: **Show the tags inside each group**, **Show Inspection Limitations line**, **Show Informational Notes line**, **Show "N of these are listed in the Deficiency Summary"** and **Show Counts**.
- **Icon Style**.

The toolbar's **Summary appears** dropdown sets where the summary goes. On TREC it reads **Summary appears: at the end (required)**.

If the template uses a Guided Layout summary, a warning says your canvas edits won't print. Click **Use this canvas page** to print the canvas instead.

### When to use the Visual Page Designer

Use it when Guided Layout doesn't give you enough control:

- Commercial or specialty report layouts that don't fit a standard blueprint
- Custom header or footer that isn't part of the standard
- A non-standard section ordering
- Special pages for specific inspection types

For a standard residential template on TREC or InterNACHI, Guided Layout plus the Cover Designer is almost always enough.

## Cover page lives separately

The report cover is built in **Cover Designer** (its own top-nav item), not in the Visual Page Designer. See [Cover page and report layout](/1nspect/getting-started/cover-and-layout).
